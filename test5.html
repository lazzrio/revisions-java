Pour les réussir il ne faut pas apprendre par cœur : il faut savoir dérouler le code dans sa tête. Chaque partie ci-dessous montre donc du vrai code, commenté, avec son déroulé.

Stratégie pendant le test

  1. 35 secondes par question. Si tu hésites, élimine d'abord les réponses fausses, choisis la plus probable et avance : on ne peut pas revenir.

  4. Les réponses sont mélangées : ne retiens pas la position, retiens la raison.
Semaine 5 · cours 5

Exceptions : comprendre le déroulé

Une exception est un objet qui interrompt l'exécution normale. Il « remonte » la pile d'appels jusqu'au premier catch compatible. S'il n'y en a pas, le programme s'arrête avec la trace.

1. La hiérarchie à connaître

Throwable
├── Error                         // erreurs graves de la JVM : on ne les traite pas (StackOverflowError, OutOfMemoryError)
└── Exception                     // à traiter
    ├── RuntimeException          // NON vérifiées : erreurs de programmation, aucune obligation
    │     NullPointerException, ArithmeticException, ArrayIndexOutOfBoundsException,
    │     ClassCastException, NumberFormatException (⊂ IllegalArgumentException), IllegalStateException
    └── toutes les autres         // VÉRIFIÉES : try/catch ou throws OBLIGATOIRE
          IOException ⊃ FileNotFoundException, ClassNotFoundException, tes propres « extends Exception »

Question type : « laquelle est non vérifiée ? » → celle qui passe par RuntimeException.

2. Une exception personnalisée, ligne par ligne

class SoldeInsuffisantException extends Exception {        // (1) extends Exception → VÉRIFIÉE
    public SoldeInsuffisantException(double manque) {
        super("Il manque " + manque + " EUR");              // (2) le message va au parent → getMessage() le renverra
    }
}

class Compte {
    private double solde;
    public void retirer(double m) throws SoldeInsuffisantException {   // (3) on DÉCLARE ce qui peut sortir
        if (m > solde)
            throw new SoldeInsuffisantException(m - solde);            // (4) on LANCE : la méthode s'arrête ici
        solde -= m;                                                    // (5) jamais atteint si on a lancé
    }
}

public class Main {
    public static void main(String[] args) {
        Compte c = new Compte();
        try {                                                // (6) zone surveillée
            c.retirer(50);
            System.out.println("Retrait OK");                // sauté si l'exception est lancée
        } catch (SoldeInsuffisantException e) {              // (7) traitement
            System.out.println(e.getMessage());              // → Il manque 50.0 EUR
        } finally {                                          // (8) toujours exécuté
            System.out.println("Fin de l'opération");
        }
    }
}

À retenir

  • (1) vérifiée ⇒ (3) throws obligatoire dans la méthode qui lance.
  • (2) sans super(message), getMessage() renvoie null.
  • (4) throw = instruction qui lance un objet.
  • (7) sans le try/catch (ou un throws sur main), l'appel c.retirer(50) ne compile pas.

Sortie ici

Le solde vaut 0, on retire 50 : m > solde, on lance. Rien n'affiche « Retrait OK ».

Il manque 50.0 EUR
Fin de l'opération

3. Suivre l'exécution : la pile d'appels

static void a() { System.out.println("a1"); b(); System.out.println("a2"); }
static void b() { System.out.println("b1"); throw new IllegalStateException("boum"); }
public static void main(String[] args) {
    try { a(); }
    catch (RuntimeException e) { System.out.println("main:" + e.getMessage()); }
}
ÉtapePile d'appelsAffichage
main entre dans le try, appelle a()main → a
a affiche, appelle b()main → a → ba1
b affiche puis lance l'exceptionmain → a → bb1
b n'a pas de catch : on dépile, a non plus (a2 est sauté)main
main a un catch compatible (IllegalStateException ⊂ RuntimeException)mainmain:boum

Une non vérifiée (RuntimeException) n'a pas besoin de throws : c'est pour cela que b et a compilent sans rien déclarer.

4. finally : les cas qui piègent

return dans le try

static int f() {
    try { return 1; }
    finally { System.out.println("F"); }
}
// println(f()) → F puis 1

La valeur est préparée, le finally s'exécute, puis la méthode se termine.

return dans le finally

static int g() {
    try { return 1; }
    finally { return 2; }
}
// g() → 2

Le return du finally écrase celui du try.

variable modifiée dans finally

static int h() {
    int x = 1;
    try { return x; }
    finally { x = 99; }
}
// h() → 1

La valeur renvoyée est copiée avant le finally.

continue dans une boucle

for (int i = 0; i < 3; i++) {
    try {
        if (i == 1) continue;
        System.out.println("i=" + i);
    } finally { System.out.println("f" + i); }
}
// i=0 f0 f1 i=2 f2

finally s'exécute à chaque tour, même quand on saute avec continue.

6. try-with-resources

try (R a = new R("A"); R b = new R("B")) {     // ressources déclarées entre parenthèses
    System.out.println("body");
}                                               // fermeture automatique dans l'ordre INVERSE
// open A / open B / body / close B / close A

Condition : la classe implémente AutoCloseable (FileReader, Scanner, PrintWriter, ObjectOutputStream le font). On ne ferme plus à la main.

Semaine 5 · cours 5 · TP5

Fichiers texte et sérialisation : comprendre le code

Deux façons de sauvegarder : en texte (une ligne par objet, champs séparés par ;) ou en binaire (on sérialise des objets entiers).

1. Fichier texte : écrire puis relire

// ÉCRITURE
try (PrintWriter out = new PrintWriter(new FileWriter("notes.txt"))) {   // FileWriter(nom) ÉCRASE ; (nom, true) AJOUTE
    out.println("Alice;20;15.5");                                       // une ligne par objet
    out.println("Bilal;21;12.0");
} catch (IOException e) {                                               // l'ouverture peut échouer
    System.out.println("Écriture impossible : " + e.getMessage());
}                                                                       // close() automatique → tampon vidé

// LECTURE
try {
    Scanner sc = new Scanner(new File("notes.txt"));    // lance FileNotFoundException (vérifiée)
    while (sc.hasNextLine()) {                           // tant qu'il reste une ligne
        String[] champs = sc.nextLine().split(";");      // {"Alice", "20", "15.5"} : des String !
        String nom = champs[0];
        int age = Integer.parseInt(champs[1]);           // String → int
        double moy = Double.parseDouble(champs[2]);      // String → double
        System.out.println(nom + " a " + age + " ans, moyenne " + moy);
    }
    sc.close();
} catch (FileNotFoundException e) {                      // fichier absent
    System.out.println("Fichier introuvable : " + e.getMessage());
}

Les quatre pièges

  • new File("x") représente un chemin, il ne crée pas le fichier.
  • split(";") donne des String ; "a;b;;".split(";").length vaut 2 (vides finales supprimées).
  • Sans close() (ou try-with-resources), l'écriture peut ne jamais arriver dans le fichier.
  • FileNotFoundException avant IOException dans les catch.

Lire / écrire : qui est qui ?

  • Lire du texte : Scanner (+ File), BufferedReader.readLine() (renvoie null à la fin).
  • Écrire du texte : PrintWriter, FileWriter, BufferedWriter.
  • Octets : FileInputStream / FileOutputStream.
  • Objets : ObjectInputStream / ObjectOutputStream.

2. Sérialisation : sauver et recharger une liste

public class Etu implements Serializable {                   // (1) marqueur : aucune méthode à écrire
    private static final long serialVersionUID = 1L;         // (2) numéro de version de la classe
    private String nom;
    private double moyenne;
    private transient String motDePasse;                     // (3) NON sauvegardé

    // constructeur, toString ...

    static void sauver(List<Etu> liste, String fichier) throws IOException {
        try (ObjectOutputStream out = new ObjectOutputStream(new FileOutputStream(fichier))) {  // (4) flux d'objets AUTOUR d'un flux d'octets
            out.writeObject(liste);                          // (5) toute la liste (et ses éléments) en un appel
        }
    }

    @SuppressWarnings("unchecked")
    static List<Etu> charger(String fichier) throws IOException, ClassNotFoundException {
        try (ObjectInputStream in = new ObjectInputStream(new FileInputStream(fichier))) {
            return (List<Etu>) in.readObject();              // (6) readObject() renvoie Object → CAST
        }
    }
}

Que se passe-t-il à la relecture ?

// écrit : Alice 15.5 "secret"
// relu  : Alice 15.5 null

motDePasse est transient : il revient à la valeur par défaut (null pour un objet, 0 pour un int, false pour un boolean). Aucun constructeur n'est rappelé.

Ce que la sérialisation ne sauve pas

  • Les attributs transient.
  • Les attributs static (ils appartiennent à la classe).
  • Si un attribut est d'une classe non sérialisable : NotSerializableException à l'exécution.

Détails qui tombent au QCM

  • On relit dans le même ordre qu'on a écrit.
  • Un objet référencé deux fois dans le flux reste un seul objet après relecture.
  • Fin des objets : EOFException.
  • Serializable s'hérite : JFrame est sérialisable, d'où l'avertissement serialVersionUID.

Swing, layouts et listeners : comprendre le code

Une interface = des composants placés dans des conteneurs par des layouts, plus des listeners qui réagissent aux événements (clic, clavier, souris).

1. Une fenêtre minimale

public class IHMTel extends JFrame {                         // la fenêtre EST une JFrame
    public void affiche() {
        JTextField textField = new JTextField(" ", 25);       // champ de 25 colonnes
        textField.setEditable(false);                         // lecture seule
        JButton buttonOk = new JButton("OK");
        this.setDefaultCloseOperation(JFrame.EXIT_ON_CLOSE);  // fermer la fenêtre = arrêter le programme
        setLayout(new BorderLayout());                        // (déjà le layout par défaut d'une JFrame)
        add("North", textField);                              // en haut
        add("Center", buttonOk);                              // au milieu
        Cadran cadran = new Cadran(textField, buttonOk);      // le pavé (JPanel) reçoit les composants qu'il doit piloter
        add("South", cadran);                                 // en bas
        pack();                                               // taille = taille préférée du contenu
        setVisible(true);                                     // sans ça : fenêtre invisible
    }
}
public class Utilisation {
    public static void main(String[] args) {
        SwingUtilities.invokeLater(() -> new IHMTel().affiche());   // l'IHM se construit dans le thread de Swing (EDT)
    }
}

4. Le Cadran du TP, ligne par ligne

public class Cadran extends JPanel implements ActionListener {   // un JPanel qui s'écoute lui-même
    JTextField textfield;  JButton buttonOk;
    JButton buttons[] = new JButton[9];                          // les touches 1 à 9
    JButton buttonBis = new JButton("Bis"), buttonZero = new JButton("0"), buttonReset = new JButton("Reset");
    private String numeroValide = "";                            // mémoire pour « Bis »

    Cadran(JTextField t, JButton ok) {
        this.textfield = t;  this.buttonOk = ok;
        setLayout(new GridLayout(4, 3));                         // 4 lignes × 3 colonnes = 12 touches
        for (int i = 0; i < buttons.length; i++) {
            add(buttons[i] = new JButton("" + (i + 1)));         // crée, ajoute, mémorise
            buttons[i].addActionListener(this);                  // CE panneau reçoit les clics
        }
        add(buttonBis); add(buttonZero); add(buttonReset);
        buttonZero.addActionListener(this);  buttonBis.addActionListener(this);
        buttonReset.addActionListener(this); buttonOk.addActionListener(this);   // OK appartient à IHMTel mais est écouté ici
    }

    @Override
    public void actionPerformed(ActionEvent e) {                 // UNE méthode pour tous les boutons
        Object source = e.getSource();                           // qui a été cliqué ?
        String affiche = textfield.getText();
        if (source == buttonReset)        textfield.setText("");              // vider
        else if (source == buttonOk)      numeroValide = affiche;             // mémoriser
        else if (source == buttonBis)     textfield.setText(numeroValide);    // rappeler
        else if (affiche.length() < 8)    textfield.setText(affiche + ((JButton) source).getText());   // ajouter un chiffre
    }
}

MVC : comprendre qui fait quoi

Trois rôles. Le modèle sait calculer, la vue sait afficher, le contrôleur sait réagir. Aucun ne fait le travail d'un autre.

Le compteur MVC, en 4 classes, expliqué

// ===== MODÈLE : données + règles. AUCUN import javax.swing =====
public interface CompteurListener { void compteurModifie(CompteurModele m); }     // contrat des observateurs

public class CompteurModele {
    private int valeur = 0;
    private final int max;
    private final List<CompteurListener> abonnes = new ArrayList<>();       // il ne connaît que l'INTERFACE
    public CompteurModele(int max) { this.max = max; }
    public int getValeur() { return valeur; }
    public void ajouterAbonne(CompteurListener l) { abonnes.add(l); }
    public void incrementer() {
        if (valeur >= max) throw new IllegalStateException("Maximum " + max + " atteint");   // règle MÉTIER → exception
        valeur++;
        prevenir();                                                      // (3) notification, après le changement
    }
    public void remettreAZero() { valeur = 0; prevenir(); }
    private void prevenir() { for (CompteurListener l : abonnes) l.compteurModifie(this); }
}
// ===== VUE : affichage seulement =====
public class CompteurVue extends JFrame implements CompteurListener {       // elle observe le modèle
    private final JLabel affichage = new JLabel("0");
    private final JLabel erreur = new JLabel(" ");
    final JButton plus = new JButton("+1");
    final JButton raz = new JButton("RAZ");
    public CompteurVue() { /* layout, add(...), EXIT_ON_CLOSE, pack() */ }
    public void ecouter(ActionListener l) { plus.addActionListener(l); raz.addActionListener(l); }   // le contrôleur s'abonne ici
    public void afficherErreur(String msg) { erreur.setText(msg); }
    @Override public void compteurModifie(CompteurModele m) {                // appelée PAR LE MODÈLE
        affichage.setText(String.valueOf(m.getValeur()));
        erreur.setText(" ");                                                 // un changement réussi efface l'erreur
    }
}

// ===== CONTRÔLEUR : clic → appel du modèle =====
public class CompteurControleur implements ActionListener {
    private final CompteurModele modele;
    private final CompteurVue vue;
    public CompteurControleur(CompteurModele m, CompteurVue v) { modele = m; vue = v; v.ecouter(this); }   // (1) s'abonne aux boutons
    @Override public void actionPerformed(ActionEvent e) {
        try {
            if (e.getSource() == vue.plus) modele.incrementer();             // (2) appelle le modèle
            else if (e.getSource() == vue.raz) modele.remettreAZero();
        } catch (IllegalStateException ex) {
            vue.afficherErreur(ex.getMessage());                             // erreur métier → message pour l'utilisateur
        }
    }
}

// ===== MAIN : crée et relie =====
SwingUtilities.invokeLater(() -> {
    CompteurModele m = new CompteurModele(5);
    CompteurVue v = new CompteurVue();
    m.ajouterAbonne(v);                  // la vue observe le modèle
    new CompteurControleur(m, v);        // le contrôleur écoute la vue
    v.setVisible(true);
});

Qui connaît qui ?

  • Contrôleur : connaît la vue et le modèle.
  • Vue : lit le modèle (ou seulement l'interface) pour s'afficher.
  • Modèle : ne connaît personne, juste une liste de CompteurListener.

Les questions classiques

  • Où va la règle « pas plus de 5 » ? Modèle.
  • Où va le JLabel ? Vue.
  • Qui implémente ActionListener ? Contrôleur.
  • Qui convertit le texte du JTextField en int ? Contrôleur.
  • Quel patron relie modèle et vue ? Observateur.
  • Comment tester le modèle ? Dans un main console, sans fenêtre.
