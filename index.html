Semaine 1

Les bases de la POO

Une classe, ses attributs, ses méthodes. Comment lire au clavier, manipuler des tableaux, distinguer static et instance.

📚 Notions clés

Classe & objet

Une classe est un plan. Un objet est une réalisation concrète en mémoire, créée avec new.

class Train { }
Train t = new Train();

Attribut vs méthode

Un attribut = variable dans la classe (donnée). Une méthode = action que l'objet sait faire.

private int vitesse; // attribut
public void stopper() { } // méthode

Encapsulation

On rend les attributs private pour les protéger, et on expose des méthodes public pour y accéder.

private String nom;
public String getNom() { return nom; }

static vs instance

static = une seule copie partagée par toute la classe. Sans static = une copie par objet.

public static int i = 10; // partagé
public int j = 20; // par objet

Tableaux

Il faut allouer avec new avant utilisation. Taille via a.length (sans parenthèses).

int[] a = new int[5];
System.out.println(a.length);

Saisie clavier

Objet Scanner pour lire. Une méthode par type : nextInt(), nextDouble(), nextLine().

Scanner s = new Scanner(System.in);
int n = s.nextInt();

import java.util.Scanner;

class Etudiant {

Exercice pratique — pas de code à lire, à faire toi-même

javac Train.java compile le fichier source en Train.class dans le même dossier src, s'il n'y a aucune erreur. Ensuite java Train exécute le programme (sans l'extension .class, juste le nom de la classe).

Si tu introduis une erreur volontaire (ex : oublier un ;, une accolade), javac refuse de produire le .class et affiche le numéro de ligne + la nature de l'erreur dans le terminal. C'est le comportement normal : la compilation échoue avant même de pouvoir exécuter quoi que ce soit.

cours1_train.zip — Train.java 
public class Train {
    public int vitesse, marche;
    public Train() { vitesse=0; marche=0; } // constructeur SANS paramètre
    public void stopper() { }  // méthode vide, à compléter
    public static void main(String[] argv) {
        Train trainsdi = new Train();
        trainsdi.stopper();
        System.out.println("Vitesse = "+trainsdi.vitesse);
    }
}

Constructeur par défaut = sans paramètre, appelé automatiquement par new Train(). Il initialise vitesse et marche à 0 pour garantir un état de départ cohérent, plutôt que de laisser des valeurs indéterminées.

Rôle de chaque bloc : le constructeur initialise, stopper() est destinée à remettre vitesse/marche à 0 (vide ici, à compléter), et main orchestre tout : crée l'objet, appelle stopper(), affiche l'état.

Conclusion : même si stopper() ne fait encore rien, l'affichage montre vitesse=0 car c'est le constructeur qui l'a déjà initialisé à 0 — la preuve que le constructeur s'exécute systématiquement avant tout appel de méthode sur l'objet.

cours1_string.zip — Main.java

Initialiser un String : String s = "texte"; (littéral, le plus courant) ou new String("texte") (équivalent en contenu). Chaîne vide : String vide = ""; (guillemets collés, sans espace) ou new String().

Concaténer : l'opérateur + — "abc" + "def" → "abcdef".

Copier : String s2 = s1; copie la référence (les deux noms pointent le même objet). Comme les String sont immuables, ça ne pose aucun problème pratique — contrairement aux tableaux vus plus loin.

String → int : int i = Integer.parseInt(chaine); — intérêt : pouvoir faire des calculs sur une valeur saisie au clavier (qui arrive toujours en String).

int → String : String s = String.valueOf(n); — intérêt : afficher/concaténer un nombre avec du texte proprement.

String → float : float f = Float.parseFloat(chaine); — même logique que pour int, pour les valeurs décimales.

cours1_arguments.zip — Main.java 
args = new String[]{"1", "2"};
System.out.println("Nom : "+args[0]);                      // ligne 4
System.out.println("Nom : "+Integer.parseInt(args[1]));    // ligne 5

Ligne 4 : args[0] vaut "1" (une String). L'affichage "Nom : 1" vient d'une simple concaténation de texte.

Ligne 5 : args[1] vaut "2" (String aussi), mais Integer.parseInt(args[1]) la convertit en int avant l'affichage. Le résultat affiché ("Nom : 2") ressemble à celui de la ligne 4, mais la nature de la valeur manipulée est différente : String pour la ligne 4, int pour la ligne 5.

À retenir : les arguments de main sont toujours reçus comme des String, même s'ils "ressemblent" à des nombres — il faut explicitement les convertir avec parseInt/parseFloat pour faire des calculs dessus.

cours1_train2.zip — Conducteur.java 
public class Conducteur {
    public static Train trainsdi = new Train();
    public static void main(String[] argv) {
        trainsdi.stopper();
        System.out.println("Vitesse = "+trainsdi.vitesse);

Pourquoi static : sur trainsdi et sur main, ça permet d'utiliser l'attribut et la méthode sans créer d'objet Conducteur au préalable — cohérent avec le fait que main est toujours static (point d'entrée exécuté directement par la JVM).

Relation Conducteur/Train : Conducteur possède une référence vers un objet Train (attribut) — c'est une relation d'agrégation (Train existe "attaché" à Conducteur).

Instanciation et appel : public static Train trainsdi = new Train(); crée l'objet directement à la déclaration. trainsdi.stopper(); envoie ensuite un message (appel de méthode) à cet objet — "le conducteur n'a pas besoin de savoir comment le train s'arrête, c'est la responsabilité du train".

cours1_tableaux.zip — Main.java

Remarque sur la taille : elle n'est pas fixée à la déclaration (int[] a;) mais seulement à l'instanciation (a = new int[5];). Deux tableaux du même type déclaré peuvent avoir des tailles totalement différentes.

Manières d'instancier : new int[5] (taille explicite, cases initialisées à 0) ou en donnant directement les valeurs : int[] a = {1, 40, 3, 6, 3}; (taille déduite du nombre de valeurs).

Propriété de taille : a.length — c'est un attribut, donc sans parenthèses (contrairement à s.length() sur une String).

Parcourir : une boucle for classique, de i=0 jusqu'à i < a.length.

cours1_tableau_muldimension.zip — Main.java

Instanciation fixe : int[][] tab = {{11,12,13},{21,22,23}}; — dimensions et valeurs connues d'avance.

Instanciation "en escalier" : int[][] tab2 = new int[3][]; puis, ligne par ligne : tab2[i] = new int[taille]; — chaque ligne peut avoir une longueur différente (le tableau n'est pas obligatoirement rectangulaire).

Parcours : deux boucles for imbriquées — i pour les lignes (i<tab.length), j pour les colonnes (j<tab[i].length).

Nombre aléatoire : (int)(Math.random()*10) — Math.random() renvoie un double entre 0.0 (inclus) et 1.0 (exclu), qu'on multiplie par 10 puis qu'on caste en int pour obtenir un entier entre 0 et 9.

Suite de cours1_tableau_muldimension.zip 
int[][] tab3 = tab;  // copie la RÉFÉRENCE, pas le contenu

    for (int j = 0; j < tab3[i].length; j++)

TP1 — questions de réflexion officielles du sujet

Pourquoi séparer Main et Etudiant : ça respecte le principe d'encapsulation / séparation des responsabilités. Etudiant représente une entité métier (un étudiant et son comportement), Main représente le point d'entrée qui orchestre le programme. Mélanger les deux romprait la lisibilité et empêcherait de réutiliser Etudiant dans un autre programme.

Pourquoi on ne peut pas afficher directement eleve.nom depuis Main : les attributs de Etudiant sont déclarés private — accessibles uniquement à l'intérieur de la classe Etudiant elle-même. Depuis l'extérieur (Main), ils sont invisibles.

Solution proposée : exposer des méthodes publiques (ici afficherInfos(), et les getters comme getNom()) que Main peut appeler pour interagir avec l'objet, sans jamais toucher directement à ses attributs privés. C'est exactement le mécanisme d'encapsulation vu en semaine 1.

public class Villain {

public class Orc extends Villain {

Les 5 mécanismes de l'héritage — un par un

Pas juste "comment les repérer" — ce que chacun fait vraiment quand le programme s'exécute.

Ça dit à Java : "un Mammifere EST UNE SORTE DE Vertebres." Concrètement, Mammifere reçoit automatiquement tout ce que Vertebres possède (méthodes publiques/protected), sans les réécrire.

Analogie : hériter d'une maison de famille — pas besoin de reconstruire les fondations, elles sont déjà là.

Un objet Mammifere contient deux parties : la partie "Vertebres" (héritée) et la partie "Mammifere" (propre). super(30) dit : "avant tout, va exécuter le constructeur Vertebres(int) avec 30."

public class Mammifere extends Vertebres {
    public Mammifere() {
        super(30);  // DOIT être la 1ère ligne
    }
}

Sans ça, la partie héritée ne serait jamais initialisée proprement — Java t'oblige à le préciser dès que le parent n'a pas de constructeur simple.

Différent de super(...) : ici on appelle une méthode normale du parent, pas le constructeur.

public void afficher() {
    super.afficher();   // exécute D'ABORD la version du parent
    System.out.println("...et un Orc !");  // PUIS ajoute ma ligne
}

Sans super.afficher(), la version du parent ne s'afficherait jamais — la méthode d'Orc remplace complètement celle du parent. super.methode() permet de réutiliser l'ancien comportement au lieu de le perdre.

protected = "je le cache au monde extérieur, mais je le montre à mes enfants (sous-classes)." Compromis entre private (personne) et public (tout le monde).

@Override ne change rien à l'exécution. Il sert uniquement à te protéger d'une faute de frappe.

@Override
public void Afficher() { ... }   // "A" majuscule par erreur !

Sans @Override : Java ne remarque rien, il crée juste une nouvelle méthode sans lien avec le parent — bug silencieux découvert bien plus tard.

Avec @Override : Java vérifie qu'une méthode afficher() existe vraiment dans le parent avec la même signature. Faute de frappe → erreur de compilation immédiate.

Question conceptuelle sur diagramme UML

La relation typique Maison/Personne est une association (voire une agrégation) : une Personne "habite" une Maison. Une association relie deux classes sans hiérarchie particulière — contrairement à l'héritage, aucune classe n'est une "spécialisation" de l'autre.

class Oeuvre {

📚 Notions clés

Surcharge de constructeurs

Plusieurs constructeurs, même nom (celui de la classe), signatures différentes. Java choisit selon les arguments fournis à new.

Point() / Point(x,y) / Point(x,y,nom)

this() — chaîner les constructeurs

Un constructeur peut appeler un autre constructeur de la même classe, en 1ère ligne, pour éviter de dupliquer du code d'initialisation.

Point(x,y) { this(); this.x=x; ... }

this — auto-référence

Désigne l'objet courant. Sert à lever l'ambiguïté attribut/paramètre, ou à retourner une référence vers soi-même.

public Point getReferenceToMe() { return this; }

toString() + @Override

Méthode héritée de la classe Object (la mère de toutes les classes). La redéfinir change ce qu'affiche println(objet).

@Override public String toString() { return "..."; }

equals() vs ==

== compare les références (adresses). equals(), hérité d'Object, compare par défaut aussi les références — sauf si on le redéfinit.

a.equals(b) // false si a et b sont 2 objets différents, même avec le même contenu

Affectation d'objets

a = b; ne copie pas le contenu — ça copie la référence. Après ça, a et b désignent le même objet, et les anciennes valeurs de a sont perdues (accessibles nulle part).

a = b; // a pointe maintenant vers l'objet de b

Packages

Regroupe des classes liées sous un même nom. Une classe indique son package en 1ère ligne, et importe les classes des autres packages avec import.

package individu; import transport.*;

Surcharge de méthodes

Même principe que les constructeurs : plusieurs méthodes du même nom, signatures différentes (nombre/type de paramètres).

translater(int,int) — Point vs translater(Point,Point) — Segment

Redéfinir equals() — comparer le CONTENU au lieu de la référence

public class Complexe {
    private double reel;   // partie réelle
    private double img;    // partie imaginaire

    public Complexe(double r, double i) { reel = r; img = i; }

    @Override
    public boolean equals(Object autre) {
        // 1) securite : autre ne doit pas etre null
        if (autre == null) return false;

        // 2) verifie qu'on compare deux objets de la MEME classe
        if (this.getClass() != autre.getClass()) return false;

        // 3) transtypage : autre est un Object, on le voit comme un Complexe
        Complexe c = (Complexe) autre;

        // 4) compare le CONTENU (reel ET img)
        return this.reel == c.reel && this.img == c.img;
    }
}

// utilisation ------------------------------------------------------
Complexe a = new Complexe(1.0, 2.0);
Complexe b = new Complexe(1.0, 2.0);

a.equals(b);   // true  : meme contenu (grace au equals() redefini)
a == b;         // false : 2 objets differents en memoire

Sans cette redéfinition, a.equals(b) renverrait false (comportement hérité d'Object = compare les références). Les 4 étapes sont le patron classique : null → getClass → cast → comparer chaque attribut.

Polymorphisme, classes abstraites, interfaces, collections

Après l'héritage (S2) et les concepts de base (S3), on monte d'un cran : on oblige les filles à implémenter certaines méthodes (abstract), on définit des contrats multi-classes (interface), et on exploite l'appel polymorphe avec les collections triables (Comparable/Comparator).

📚 Notions clés

Classe abstraite

Classe non instanciable qui peut contenir des méthodes abstract (déclarées sans corps). Les filles concrètes doivent toutes les redéfinir.

public abstract class Personnels { public abstract void travailler(int h); }

Méthode abstraite

Déclarée dans une classe abstraite avec abstract, se termine par ; (pas de {}). Force chaque sous-classe à fournir sa propre implémentation.

public abstract double getSurface();

Interface

100 % contrat : liste de méthodes que la classe qui l'implements doit fournir. Pas d'attribut d'état, pas de constructeur.

interface Sportif { public void jouer(); }

implements (multiple)

Contrairement à extends (une seule classe mère), une classe peut implements plusieurs interfaces en même temps, séparées par virgules.

class Personne implements Client, Employe, Sportif

Polymorphisme

Une variable du type parent peut désigner un objet fille ; la méthode appelée est celle de la classe réelle de l'objet, pas du type déclaré.

Instrument i = new Wind(); i.play(); // appelle Wind.play()

Argument polymorphe

Une méthode qui prend un paramètre du type parent accepte n'importe quelle fille — sans savoir à l'avance laquelle.

static void tune(Instrument i) { i.play(...); }

Collections (List, Vector)

Tableaux dynamiques génériques : List<T>, Vector<T>, ArrayList<T>. Taille automatique, add(), get(i), size().

List<Forme> l = new Vector<Forme>();

Comparable vs Comparator

Comparable : ordre naturel dans la classe (compareTo). Comparator : ordre externe défini ailleurs, souvent comme classe anonyme.

Collections.sort(l); // natural / Collections.sort(l, cmp);

cours4_interface.zip

Rôle des 3 interfaces. Chacune est un contrat : la liste des services qu'une classe promet de rendre, sans dire comment. Client = commander et acheter, Employe = travailler, Sportif = jouer. Elles décrivent des rôles qu'une même personne peut jouer.

Relation. Personne réalise (implémente) les trois interfaces, avec le mot Java implements : public class Personne implements Client, Employe, Sportif. En UML : flèche pointillée à tête triangulaire vide vers chaque interface. C'est la façon Java d'obtenir un « héritage multiple » de types (une seule classe mère avec extends, mais autant d'interfaces qu'on veut).

Dans Personne, obligatoire : écrire le corps des 4 méthodes commander(), acheter(), travailler(), jouer(), en public (les méthodes d'interface sont implicitement public abstract, on ne peut pas réduire la visibilité). Sinon erreur de compilation, sauf si Personne est déclarée abstract.

Pourquoi on ne peut instancier que Personne. Une interface n'a ni attribut d'état ni constructeur ni code : il n'y a rien à construire. new Client() → Client is abstract; cannot be instantiated. On peut en revanche l'utiliser comme type :

Client c = new Personne();   // OK : une Personne EST un Client
c.commander();               // OK
c.jouer();                   // ERREUR de compilation : le type Client ne connaît pas jouer()
((Personne) c).jouer();      // OK après downcast

Pourquoi une interface ? Les trois animaux font les trois actions chacun à sa manière : il n'y a aucun code commun à factoriser, seulement un contrat. Une classe concrète Animal serait mauvaise (on devrait écrire un faireSon() par défaut qui n'a pas de sens, et on pourrait créer « un animal » générique). public interface Animal {
    void manger();
    void dormir();
    void faireSon();
}

public class Chien implements Animal {
    private String nom;
    private String race;
    private int nbOs;                       // attribut propre au chien

    public Chien(String nom, String race) { this.nom = nom; this.race = race; this.nbOs = 0; }

    @Override public void manger()   { System.out.println(nom + " (" + race + ") ronge un os"); }
    @Override public void dormir()   { System.out.println(nom + " dort dans sa niche"); }
    @Override public void faireSon() { System.out.println(nom + " : Wouf !"); }

    public void enterrerOs() { nbOs++; System.out.println(nom + " a enterré " + nbOs + " os"); }
}
// Chat (nom, nbVies = 9, griffer()) et Oiseau (nom, envergure, voler()) : même schéma

public class Zoo {
    static void nourrir(Animal a) {
        a.manger();                          // polymorphe : pas besoin de connaître le type
        if (a instanceof Chien) {            // 1) tester le type réel
            Chien c = (Chien) a;             // 2) downcast, sûr grâce au test

        } else if (a instanceof Oiseau) {

        } else if (a instanceof Chat) {

        }
    }

📚 Notions clés

Exception

Objet qui décrit une erreur à l'exécution. Quand elle est lancée, l'exécution normale s'arrête et « remonte » la pile des appels jusqu'au premier catch compatible. Sinon : le programme s'arrête avec la trace (stack trace).

throw new IllegalArgumentException("âge négatif");

throw vs throws

throw (dans le corps) lance une exception. throws (dans la signature) annonce que la méthode peut en laisser sortir une.

void payer() throws SoldeException { … throw new SoldeException(); }

try / catch / finally

try = zone surveillée. catch = gestionnaires, du plus précis au plus général ; un seul s'exécute. finally = s'exécute toujours (succès, exception, return, continue), sauf System.exit().

try { … } catch (FileNotFoundException e) { … } finally { … }

Contrôlée ou non ?

Contrôlée (hérite de Exception mais pas de RuntimeException) : le compilateur oblige à la traiter ou à la déclarer (IOException, les tiennes). Non contrôlée (RuntimeException : NullPointerException, NumberFormatException, ArithmeticException…) : pas d'obligation.

unreported exception IOException; must be caught or declared to be thrown

Exception personnalisée

Une classe qui extends Exception (contrôlée) ou RuntimeException. On passe le message au parent avec super(msg) pour que getMessage() le renvoie.

class AgeOver extends Exception { AgeOver(String m){ super(m); } }

La classe File

Représente un chemin (fichier ou dossier), pas son contenu : exists(), length(), isDirectory(), listFiles(), delete(), getName().

File f = new File("menu.txt"); if (f.exists()) …

Fichier texte

Lire : new Scanner(new File(nom)) + hasNextLine()/nextLine(), ou BufferedReader. Écrire : PrintWriter/FileWriter/BufferedWriter. Une ligne = un objet, champs séparés par ; puis split(";").

String[] champs = ligne.split(";");

Sérialisation

Transformer un objet (et tous les objets qu'il référence) en octets pour le sauver ou l'envoyer, puis le reconstruire. La classe doit implements Serializable (interface sans méthode : un simple marqueur).

oos.writeObject(obj); … Obj o = (Obj) ois.readObject();

ObjectOutputStream / ObjectInputStream : le premier sérialise (transforme un objet et tout ce qu'il référence en suite d'octets et l'écrit), le second désérialise (relit les octets et reconstruit un objet identique en contenu).

Le lien avec FileOutputStream / FileInputStream : ce sont des flux emboîtés. Le FileOutputStream sait seulement écrire des octets dans un fichier ; l'ObjectOutputStream construit par-dessus sait transformer des objets en octets. Ensemble : « écrire des objets dans un fichier ». Même chose en lecture. On pourrait brancher l'ObjectOutputStream sur un autre flux (réseau…) sans changer le reste.

Pourquoi implements Serializable : c'est une autorisation. Sans elle, writeObject lance NotSerializableException à l'exécution. Il n'y a aucune méthode à implémenter : l'interface est vide, c'est un marqueur. Ses attributs (String, int) sont eux-mêmes sérialisables.

save : throws IOException parce que l'ouverture du fichier et l'écriture peuvent échouer (disque plein, dossier interdit…) et que la méthode choisit de ne pas traiter l'erreur : elle la propage à l'appelant (le catch (IOException exc) de CustomerDriver).         this.buttonOk = buttonOkParam;

        for (int i = 0; i < buttons.length; i++) {
            add(buttons[i] = new JButton("" + (i + 1)));
            buttons[i].addActionListener(this);        // abonner chaque chiffre

        add(buttonBis); add(buttonZero); add(buttonReset);
        buttonZero.addActionListener(this);
        buttonBis.addActionListener(this);
        buttonReset.addActionListener(this);

        textfield.setText("");

    @Override

        String affiche = textfield.getText();
        if (source == buttonReset) {                   // 3) effacer

Le pattern MVC : Modèle – Vue – Contrôleur

Il n'y a pas de PDF pour ce cours (seulement des liens Wikipedia et OpenClassrooms) : voici l'essentiel, appliqué à Swing, avec un exemple complet qui compile. Le Test 5 (50 questions en 20 min) porte sur les semaines 5, 6 et 7.

📚 Notions clés

Modèle

Les données et les règles métier (calculs, vérifications, exceptions, sauvegarde). Il ne sait rien de l'affichage : aucun import javax.swing. Il prévient ses observateurs quand il change.

class PanierModele { List<Plat> plats; double total(); void ajouter(Plat p) }

Vue

L'affichage (fenêtre, composants, layouts). Elle lit le modèle pour se redessiner mais ne contient aucune règle métier et ne décide pas quoi faire d'un clic.

class PanierVue extends JPanel { void rafraichir(PanierModele m) }

Contrôleur

Le chef d'orchestre : il écoute les actions de l'utilisateur sur la vue (ActionListener), appelle la bonne méthode du modèle, et transforme les exceptions en messages pour la vue.

class PanierControleur implements ActionListener

Le cycle

1) l'utilisateur clique dans la Vue → 2) le Contrôleur reçoit l'événement → 3) il appelle le Modèle → 4) le modèle change et notifie → 5) la Vue se met à jour.

Vue → Contrôleur → Modèle → (notification) → Vue

Pourquoi séparer ?

Maintenance (changer l'affichage sans toucher aux calculs), tests (tester le modèle sans fenêtre), réutilisation (même modèle pour une vue console, Swing ou Web), travail en équipe (un étudiant par couche).

Patron Observateur

Le modèle garde une liste d'abonnés (interface ModeleListener) et les prévient à chaque changement. Il ne connaît pas leur classe : on peut brancher plusieurs vues.

for (ModeleListener l : abonnes) l.modeleModifie(this);

En packages

Un package par couche : modele, vue, controleur, plus un Main qui crée M, V, C et les relie. C'est ce que le TP7 veut voir dans les captures.

fastbite.modele / fastbite.vue / fastbite.controleur

Qui connaît qui ?

Le contrôleur connaît la vue et le modèle. La vue connaît le modèle (en lecture) ou seulement l'interface d'observation. Le modèle ne connaît personne (juste une liste d'abonnés).

Exemple complet

Un compteur en MVC (4 classes, compile tel quel)

// Imports : java.util.* pour le modèle ; javax.swing.*, java.awt.*, java.awt.event.* pour la vue,
// le contrôleur et le main. Ne pas mettre java.awt.* ET java.util.* dans le même fichier si l'on
// écrit List : « reference to List is ambiguous » (java.awt.List existe aussi).

// ===== MODÈLE : données + règles, aucun Swing =====
public interface CompteurListener { void compteurModifie(CompteurModele m); }

public class CompteurModele {
    private int valeur = 0;
    private final int max;
    private final List<CompteurListener> abonnes = new ArrayList<>();

    public CompteurModele(int max) { this.max = max; }
    public int getValeur() { return valeur; }
    public void ajouterAbonne(CompteurListener l) { abonnes.add(l); }

    public void incrementer() {
        if (valeur >= max) throw new IllegalStateException("Maximum " + max + " atteint");   // règle métier
        valeur++;
        prevenir();
    }
    public void remettreAZero() { valeur = 0; prevenir(); }
    private void prevenir() { for (CompteurListener l : abonnes) l.compteurModifie(this); }
}

// ===== VUE : affichage uniquement =====
public class CompteurVue extends JFrame implements CompteurListener {
    private final JLabel affichage = new JLabel("0");
    private final JLabel erreur = new JLabel(" ");
    final JButton plus = new JButton("+1");
    final JButton raz = new JButton("RAZ");

    public CompteurVue() {
        super("Compteur MVC");
        setLayout(new FlowLayout());
        add(affichage); add(plus); add(raz); add(erreur);
        setDefaultCloseOperation(EXIT_ON_CLOSE);
        pack();
    }
    public void ecouter(ActionListener l) { plus.addActionListener(l); raz.addActionListener(l); }
    public void afficherErreur(String msg) { erreur.setText(msg); }
    @Override public void compteurModifie(CompteurModele m) {      // appelée par le modèle
        affichage.setText(String.valueOf(m.getValeur()));
        erreur.setText(" ");
    }
}

// ===== CONTRÔLEUR : clic -> appel au modèle =====
public class CompteurControleur implements ActionListener {
    private final CompteurModele modele;
    private final CompteurVue vue;
    public CompteurControleur(CompteurModele m, CompteurVue v) { modele = m; vue = v; v.ecouter(this); }
    @Override public void actionPerformed(ActionEvent e) {
        try {
            if (e.getSource() == vue.plus) modele.incrementer();
            else if (e.getSource() == vue.raz) modele.remettreAZero();
        } catch (IllegalStateException ex) {
            vue.afficherErreur(ex.getMessage());                    // l'erreur métier devient un message
        }
    }
}

// ===== MAIN : on crée et on relie =====
public class AppCompteur {
    public static void main(String[] args) {
        SwingUtilities.invokeLater(() -> {
            CompteurModele m = new CompteurModele(5);
            CompteurVue v = new CompteurVue();
            m.ajouterAbonne(v);                  // la vue observe le modèle
            new CompteurControleur(m, v);        // le contrôleur écoute la vue
            v.setVisible(true);
        });
    }
}
Le test qui prouve que c'est bien du MVCOn peut écrire un main console qui utilise CompteurModele sans aucune fenêtre (m.incrementer(); System.out.println(m.getValeur());). Si le modèle ne peut pas fonctionner sans Swing, la séparation est ratée.

ÉnoncéUn compte bancaire a un numéro (entier, fixé à la création), un titulaire (chaîne) et un solde (réel, 0 au départ).     public class CompteBancaire {
    private int numero;          // fixé à la création : pas de setter
    private String titulaire;
    private double solde;

    public CompteBancaire(int numero, String titulaire) {
        this.numero = numero;     // this. car le paramètre porte le même nom
        this.titulaire = titulaire;
        this.solde = 0;           // « 0 au départ »
    }

    public double getSolde() { return solde; }
    public int getNumero() { return numero; }

    }

    public boolean retirer(double montant) {
        if (montant <= 0 || montant > solde) return false;   // refusé
        solde -= montant;
        return true;
    }

    @Override
    public String toString() {
        return "Compte n°" + numero + " (" + titulaire + ") : " + solde + " €";
    }
}

🧱 Ça ne compile pas

  • Lire la première erreur : fichier + ligne + message. Les 20 suivantes sont souvent des conséquences.
  • cannot find symbol → faute de frappe (majuscule ?), variable déclarée dans un autre bloc { }, import manquant (java.util.Scanner, java.util.ArrayList).
  • non-static … from a static context → tu appelles une méthode d'instance depuis main sans objet : crée un objet ou rends la méthode static.
  • has private access → passe par un getter/setter.
  • constructor X cannot be applied to given types → mauvais nombre/type d'arguments dans le new, ou constructeur par défaut supprimé par un constructeur à paramètres.
  • call to super must be first statement → déplacer super(...).

💥 Ça compile mais ça plante

  • Lire la stack trace de haut en bas : la 1ʳᵉ ligne = type d'exception + message ; la 1ʳᵉ ligne at …(Fichier.java:NN) qui est ton fichier = l'endroit du bug.
  • NullPointerException → un objet ou un tableau déclaré mais jamais newé, ou une case de tableau d'objets restée à null.
  • ArrayIndexOutOfBoundsException: 5 → tu as demandé l'indice 5 ; vérifie i < tab.length (pas <=).
  • InputMismatchException → nextInt() a reçu un texte ; ou le nextLine() avale le retour à la ligne laissé par nextInt() (faire un nextLine() de plus).
  • ClassCastException → downcast vers une classe dont l'objet n'est pas une instance ; tester avec instanceof avant.
  • ArithmeticException: / by zero → division entière par 0 (en double, ça donne Infinity sans planter).

🔬 Ça tourne mais le résultat est faux

  • Mettre des System.out.println aux endroits clés (« valeur de x ici : … »). Rustique, imbattable.

🧬 Object, instanceof, final, static

  • Toute classe hérite d'Object : toString(), equals(), hashCode(), getClass(). Sans redéfinition, println(obj) affiche Nom@1b6d3586.
  • obj instanceof Chien → true si l'objet réel est un Chien (ou une sous-classe). À tester avant un downcast.
  • final : variable = constante (une seule affectation) ; méthode = non redéfinissable ; classe = non héritable. Convention : static final double TVA = 0.2; en MAJUSCULES.
  • static : appartient à la classe, pas à l'objet. Une méthode static ne peut pas utiliser this ni les attributs d'instance.
  • Passage de paramètres : les primitifs sont copiés (la méthode ne peut pas modifier ton int), les objets sont passés par référence (la méthode peut modifier l'objet, mais pas te faire pointer ailleurs).

📁 Fichiers, compilation, conventions

  • Une classe public par fichier, même nom que le fichier : Train → Train.java.
  • javac Train.java crée Train.class ; java Train exécute (sans extension). Le main est le point d'entrée, toujours public static void main(String[] args).
  • Nommage : classes en PascalCase, méthodes/variables en camelCase, constantes en MAJUSCULES. Getters getX(), booléens isX(), setters setX(...).
  • Un bloc { } = une portée : une variable déclarée dans un for n'existe plus après.
  • Ordre dans un fichier : package, import, classe. Ordre dans une classe : attributs, constructeurs, méthodes.

import java.util.Scanner;

// ============================================================
// CLASSE : plan/moule décrivant un type d'objet (ici, un livre).
// Une classe regroupe des ATTRIBUTS (les données) et des
// MÉTHODES (les comportements).
// ============================================================
class Livre {

    // ============ ATTRIBUTS (champs / propriétés) ============
    // Ce sont les VARIABLES appartenant à chaque objet Livre.
    // "private" = accessibles UNIQUEMENT depuis l'intérieur de
    // cette classe. C'est le principe d'ENCAPSULATION : on
    // protège les données, on force l'accès via des méthodes.

    private String titre;      // ATTRIBUT de type String (chaîne)
    private String auteur;     // ATTRIBUT de type String
    private int annee;         // ATTRIBUT de type int (entier)
    private double[] notes;    // ATTRIBUT de type tableau de double
    private int nbNotes;       // ATTRIBUT compteur (nombre effectif de notes)

    // Scanner partagé pour lire l'entrée clavier (System.in)
    Scanner clavier = new Scanner(System.in);


    // ============ CONSTRUCTEURS ============
    // Un CONSTRUCTEUR est une méthode SPÉCIALE :
    //   - il porte EXACTEMENT le même nom que la classe (Livre)
    //   - il n'a PAS de type de retour, pas même void
    //   - il est appelé automatiquement par l'opérateur "new"
    // Son rôle : initialiser les attributs d'un nouvel objet.

    // -- Constructeur SANS PARAMÈTRE (dit "par défaut") --
    // Utilisé par : new Livre();
    public Livre() {
        this.titre = "Inconnu";
        this.auteur = "Anonyme";
        this.annee = 2000;
        this.nbNotes = 0;
    }

    // -- Constructeur AVEC PARAMÈTRES (dit "surchargé") --
    // Java autorise plusieurs constructeurs SI leurs listes de
    // paramètres diffèrent (nombre ou types) : c'est la SURCHARGE.
    // Utilisé par : new Livre("1984", "Orwell", 1949);
    public Livre(String titre, String auteur, int annee) {
        // "this.titre" désigne l'ATTRIBUT de l'objet.
        // "titre" tout court désigne le PARAMÈTRE de la méthode.
        // "this" est indispensable ici pour lever l'ambiguïté.
        this.titre = titre;
        this.auteur = auteur;
        this.annee = annee;
        this.nbNotes = 0;
    }


    // ============ MÉTHODES ============
    // Signature générale :
    //   [visibilité] [type_retour] nomMethode(paramètres) { ... }
    // - visibilité : public, private, protected...
    // - type_retour : void si ne retourne rien, sinon int, double, String, un objet...

    // MÉTHODE de saisie du titre (ne retourne rien -> void)
    public void saisirTitre() {
        System.out.println("Entrer le titre du livre : ");
        this.titre = clavier.nextLine();  // lit une ligne entière
    }

    // MÉTHODE de saisie de l'année avec VALIDATION dans une boucle while.
    // Rappel : while(cond) { ... } répète TANT QUE cond est vraie.
    public void saisirAnnee() {
        System.out.println("Entrer l'annee (1450-2026) : ");
        this.annee = clavier.nextInt();
        while (this.annee < 1450 || this.annee > 2026) {
            System.out.println("Annee invalide, reessayer :");
            this.annee = clavier.nextInt();
        }
    }

    // MÉTHODE qui saisit nbNotes et LE RETOURNE (type de retour : int)
    public int saisirNbNotes() {
        System.out.println("Combien de notes (1-10) ? ");
        this.nbNotes = clavier.nextInt();
        while (this.nbNotes < 1 || this.nbNotes > 10) {
            System.out.println("Doit etre entre 1 et 10, reessayer :");
            this.nbNotes = clavier.nextInt();
        }
        return this.nbNotes;  // renvoie la valeur à l'appelant
    }

    // MÉTHODE qui saisit un TABLEAU de notes.
    // "new double[nb]" : ALLOCATION du tableau, sa taille est fixée à nb.
    // Un tableau en Java a une longueur immuable après création.
    public void saisirNotes(int nb) {
        this.notes = new double[nb];
        // Boucle for : compteur i de 0 (inclus) à nb (exclus).
        for (int i = 0; i < nb; i++) {
            // Boucle do-while : exécute AU MOINS UNE FOIS le bloc,
            // puis vérifie la condition à la fin.
            do {
                System.out.println("Note " + (i + 1) + " (0-10) : ");
                this.notes[i] = clavier.nextDouble();
                if (this.notes[i] < 0 || this.notes[i] > 10) {
                    System.out.println("Note doit etre entre 0 et 10");
                }
            } while (this.notes[i] < 0 || this.notes[i] > 10);
        }
    }

    // MÉTHODE qui calcule et RETOURNE la moyenne (type de retour : double)
    public double calculerMoyenne() {
        // Cas particulier : éviter la division par zéro
        if (this.nbNotes == 0) return 0.0;

        double somme = 0.0;   // accumulateur (variable LOCALE, pas un attribut)
        for (int i = 0; i < this.nbNotes; i++) {
            somme += this.notes[i];   // équivalent à somme = somme + this.notes[i]
        }
        // somme est un double, donc division réelle (pas entière)
        return somme / this.nbNotes;
    }

    // MÉTHODE d'affichage : void (n'a rien à retourner)
    public void afficherInfos() {
        System.out.println("=== Livre ===");
        System.out.println("Titre  : " + this.titre);
        System.out.println("Auteur : " + this.auteur);
        System.out.println("Annee  : " + this.annee);
        System.out.println("Notes :");
        for (int i = 0; i < this.nbNotes; i++) {
            System.out.println("  - " + this.notes[i]);
        }
        // On peut appeler une AUTRE méthode du même objet avec this.
        System.out.println("Moyenne : " + this.calculerMoyenne());
    }
}
