Gagner des points avec un barème négatif

Dans l'annale 2025, une bonne réponse vaut +0,8 et une mauvaise réponse, plusieurs réponses ou l'absence de réponse valent −0,4. Le barème de ton évaluation (80 questions) n'est pas connu : l'examen blanc applique le même rapport 2 pour 1 et te laisse choisir si une case vide est pénalisée.

Si le vide est pénalisé

Une case vide coûte autant qu'une erreur : réponds toujours, même au hasard. Un tirage au hasard sur 4 réponses a une espérance de −0,125 point, mais laisser vide coûte −0,5 : répondre est toujours meilleur.

Si le vide vaut 0

Gain moyen par question (rapport 2 pour 1) selon le nombre de réponses encore possibles :

Le temps : 67 secondes par question

1 h 30 pour 80 questions. Premier passage : réponds en 45 secondes maximum, marque ⚑ ce qui demande une trace. Second passage : reprends les questions marquées avec le temps gagné.

Méthode pour les questions de code

  1. Compile-t-il ? Cherche d'abord l'erreur de compilation : variable non initialisée, static qui utilise un attribut, classe abstraite instanciée, interface à moitié implémentée, ordre des catch, super(...) pas en première ligne.
  2. Quel type pour le compilateur, quel type pour l'exécution ? Le type déclaré décide des méthodes autorisées, des attributs lus et du choix entre surcharges. Le type réel décide des méthodes redéfinies exécutées.
  3. Trace sur le brouillon : note les variables et les affichages pas à pas. Un constructeur appelle toujours celui de la mère d'abord.
  4. Mots-pièges : « toujours », « jamais », « seulement », « uniquement ». Ils rendent souvent une affirmation fausse.

Les pièges des chapitres 1 à 4

Pour les chapitres 5 à 7, voir la page Test 5 (20 pièges).

String== compare les adresses, equals le contenu. Les méthodes renvoient une nouvelle chaîne : s.toUpperCase(); seul ne change pas s.
Division7 / 2 vaut 3 ; 1 / 2 + 1 / 2.0 vaut 0.5. (int) tronque.
Addition et texte10 + 20 + "x" donne 30x ; 'a' + 1 donne 98.
Tableauxlength sans parenthèses ; cases à 0, false, null ; b = a copie la référence.
Passage par valeurUn objet ou un tableau passé en paramètre : on modifie le contenu, mais p = new ... ne change pas la variable de l'appelant.
staticPas de this, pas d'attribut d'instance. Les méthodes statiques sont masquées, jamais redéfinies : résolution sur le type déclaré.
ConstructeursPas hérités. Dès qu'on en écrit un, celui par défaut disparaît. super(...) / this(...) en 1re ligne. Pas de type de retour (void A() est une méthode).
Ordre d'exécutionConstructeur de la mère, puis de la fille. Une méthode redéfinie appelée dans le constructeur de la mère voit les attributs de la fille encore à 0.
Attributs et polymorphismeSeules les méthodes sont polymorphes. Mere m = new Fille(); m.x lit l'attribut de Mere.
Surcharge et type déclarém(Figure) / m(Cercle) avec Figure f = new Cercle() : m(f) appelle m(Figure).
Surcharge ≠ redéfinitionf(double) dans la fille n'est pas une redéfinition de f(int). Le type de retour seul ne différencie pas deux méthodes.
equalsRedéfinir equals(Object o), pas equals(Point p). Redéfinie avec hashCode pour HashSet / HashMap.
Visibilitéprivate < défaut (package) < protected (package + filles) < public. Une redéfinition ne peut pas réduire la visibilité.
TranstypageMontée implicite, descente explicite. Le compilateur accepte une descente plausible, l'exécution lance ClassCastException si le type réel ne convient pas.
abstractPas de new. Peut avoir constructeurs, attributs, méthodes concrètes. Une fille concrète implémente toutes les méthodes abstraites.
InterfaceMéthodes public abstract, attributs public static final, plusieurs implements, un seul extends. L'implémentation doit être public.
ArrayListremove(1) supprime l'indice 1, remove(Integer.valueOf(1)) l'objet. get hors liste : exception ; HashMap.get absent : null.
Parcours et suppressionSupprimer dans un for-each : ConcurrentModificationException. Utiliser Iterator.remove().
CollectionsHashSet : pas de doublons (via equals et hashCode). HashMap : clé unique, pas d'ordre garanti. Pas de List<int>.
Comparable / ComparatorcompareTo négatif : this avant l'autre. sort sans ordre naturel : erreur de compilation. Comparateur inversé : (x, y) -> y.compareTo(x).
