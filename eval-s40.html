L'essentiel

Une heure, sur feuille, sans IntelliJ : pas d'autocomplétion, pas de soulignement rouge. Ce qui compte, c'est d'écrire du Java qui compilerait, et de savoir justifier en une phrase.

  1. Classe, objet, new : une classe est un plan, un objet est créé par new qui appelle un constructeur. Un constructeur porte le nom de la classe et n'a aucun type de retour.
  2. Encapsulation : attributs private, accès par des getters/setters public. Savoir écrire une classe complète de tête (voir Code à savoir écrire).
  3. this a 3 usages : this.x = x (attribut vs paramètre), this(...) (autre constructeur, 1re ligne), return this.
  4. Héritage : extends (une seule mère), super(...) en 1re ligne du constructeur fille, protected visible dans les filles, @Override pour redéfinir.
  5. Les 6 relations UML et leur code : héritage → extends ; réalisation → implements ; association/agrégation → un attribut ; composition → attribut créé dans le constructeur ; dépendance → un paramètre. Cardinalité > 1 → tableau ou ArrayList.
  6. Références : a = b copie l'adresse, pas l'objet. == compare les adresses, equals() le contenu (s'il est redéfini). Toujours .equals() pour les String.
  7. static : une seule copie partagée par la classe ; on y accède par NomClasse.membre. Une méthode static ne peut pas utiliser this ni un attribut d'instance.
  8. Classe abstraite : abstract, non instanciable, peut avoir attributs, constructeurs, méthodes concrètes et abstraites (sans corps, terminées par ;). Interface : un contrat de méthodes, implements, plusieurs possibles.
  9. Polymorphisme : Mere m = new Fille(); puis m.methode() exécute la version de la classe réelle (liaison dynamique). Le compilateur, lui, ne regarde que le type déclaré.
  10. Collections : ArrayList<T> (add, get(i), size(), remove), HashMap<K,V> (put, get, containsKey, keySet(), entrySet()), tri avec Comparable / Comparator et Collections.sort.

Semaine 1 · Cours 1 et TP1

Les bases : classe, objet, tableaux, String, Scanner

Vocabulaire à savoir définir

  • Classe : modèle qui décrit des attributs (données) et des méthodes (comportements).
  • Objet / instance : exemplaire concret créé en mémoire par new.
  • Référence : variable qui contient l'adresse d'un objet (null si aucun objet).
  • Message : appel de méthode sur un objet, objet.methode(args).
  • Constructeur : méthode spéciale appelée par new, même nom que la classe, sans type de retour. Si on n'en écrit aucun, Java fournit un constructeur par défaut sans paramètre ; dès qu'on en écrit un, celui par défaut disparaît.

Types primitifs et objets

  • Primitifs : int, double, float, char, boolean, long… stockent directement la valeur.
  • Objets : String, tableaux, toutes les classes : la variable contient une référence.
  • Valeurs par défaut des attributs : 0, false, null. Une variable locale doit être initialisée avant usage.
  • final : constante, impossible à réaffecter.

static ou pas

Un attribut static existe en un seul exemplaire pour toute la classe (ex. un compteur d'objets). Sans static, chaque objet a sa copie. main est static : il s'exécute sans objet, donc il ne peut pas appeler directement une méthode d'instance ; il faut d'abord créer un objet.

Passage de paramètres

Java passe toujours une copie. Pour un int, la méthode modifie sa copie : la variable de l'appelant ne change pas. Pour un objet ou un tableau, c'est une copie de la référence : la méthode peut modifier l'objet pointé (voir Q4 et Q7).

Héritage : ce qu'il faut savoir écrire et expliquer

public class Villain {
    protected int force;                   // visible dans les classes filles
    public Villain(int force) { this.force = force; }
    public void afficher() { System.out.println("Villain " + force); }
}
public class Orc extends Villain {         // une seule classe mère
    private int rage;
    public Orc(int force, int rage) {
        super(force);                      // constructeur de la mère : 1re ligne
        this.rage = rage;
    }
    @Override                              // le compilateur vérifie la signature
    public void afficher() {
        super.afficher();                  // réutilise la version de la mère
        System.out.println("Orc, rage " + rage + ", force " + force);
    }
}
  • Les constructeurs ne s'héritent pas. Si la fille n'appelle pas super(...), Java insère super() : erreur si la mère n'a pas de constructeur sans paramètre.
  • this(...) et super(...) ne peuvent pas être tous les deux dans le même constructeur (chacun veut la 1re ligne).
  • À la construction d'une fille, le constructeur de la mère s'exécute en premier (voir Q5).
  • Upcasting implicite : Personne p = new Homme();. Downcasting explicite : Homme h = (Homme) p; ; il compile toujours, mais lève ClassCastException si l'objet n'est pas vraiment un Homme. On teste avant avec instanceof.

Encapsulation

Cacher les données (private) et n'exposer que des méthodes. Le setter peut contrôler la valeur (refuser un âge négatif) : c'est tout l'intérêt par rapport à un attribut public. Getter : public int getAge() { return age; } ; setter : public void setAge(int age) { if (age >= 0) this.age = age; }.

Surcharge (overloading)

Même nom, paramètres différents (nombre ou types) dans la même classe : plusieurs constructeurs Point(), Point(int, int), Point(int, int, String). Choisie à la compilation selon les arguments. Le type de retour seul ne suffit pas à surcharger.

Redéfinition (overriding)

Même signature dans une classe fille (ou pour une méthode héritée d'Object : toString, equals). Choisie à l'exécution selon l'objet réel. Visibilité au moins aussi large que dans la mère.

Affectation et comparaison

a = b; : a désigne désormais le même objet que b ; l'ancien objet de a, s'il n'est plus référencé, est détruit plus tard par le ramasse-miettes (garbage collector). a == b : même adresse ? a.equals(b) : même contenu, seulement si equals est redéfini (sinon il fait comme ==).

public class Point {
    private int x, y;
    private String nom;

    public Point() { this(0, 0); }                  // chaîne vers Point(int, int)
    public Point(int x, int y) { this(x, y, "sans nom"); }
    public Point(int x, int y, String nom) {
        this.x = x; this.y = y; this.nom = nom;     // this.x : l'attribut
    }

    @Override
    public String toString() {                      // appelé par println(p)
        return nom + " (" + x + ", " + y + ")";
    }

    @Override
    public boolean equals(Object o) {               // paramètre de type Object !
        if (o == null || getClass() != o.getClass()) return false;
        Point p = (Point) o;                        // downcast
        return x == p.x && y == p.y;                // comparer le contenu
    }
}

import java.util.ArrayList;

public class Serie {

    public Serie() { vecteur = new ArrayList<>(); }  // instancier !

Dans une classe fille, pour désigner la classe mère : super(...) en 1re ligne d'un constructeur appelle le constructeur de la mère (pour initialiser la partie héritée) ; super.methode() appelle la version de la mère d'une méthode redéfinie (pour la compléter au lieu de la remplacer).

On ne peut pas l'instancier avec new de la classe abstraite, et on ne peut appeler dessus que les méthodes déclarées dans la classe abstraite (pas celles propres à la fille, sauf après un downcast).

Une interface ne contient que des signatures de méthodes (un contrat), sans attribut d'état ni constructeur. Elle sert à imposer un comportement commun à des classes, et permet à une classe d'en implements plusieurs (l'équivalent Java de l'héritage multiple).

Surcharge : même nom, paramètres différents, dans la même classe ; résolue à la compilation. Ex. Point() et Point(int x, int y).

Redéfinition : même signature dans une classe fille, marquée @Override ; résolue à l'exécution selon l'objet réel (polymorphisme). Ex. toString() redéfinie dans Point, ou play(int) dans Wind extends Instrument.

Sortie, une ligne par affichage : A(), A(3), B(), --, A(), B(7).

new B() : super(3) appelle A(int), dont la 1re ligne this() appelle A() → « A() », puis « A(3) », puis la suite de B(). new B(7) : pas de super(...) écrit, Java insère super() → « A() » d'abord, puis « B(7) ». La mère est toujours construite avant la fille.

abstract class Animal {

}
class Chat extends Animal {

public class CompteBancaire {
    private String titulaire;
    private double solde;
    private static int nbComptes = 0;          // partagé par tous les comptes

    public CompteBancaire(String titulaire, double solde) {
        this.titulaire = titulaire;
        this.solde = solde;
        nbComptes++;
    }
    public CompteBancaire(String titulaire) {
        this(titulaire, 0);                    // chaînage : 1re ligne
    }

    public String getTitulaire() { return titulaire; }
    public double getSolde() { return solde; }
    public static int getNbComptes() { return nbComptes; }

    public void deposer(double montant) {
        if (montant > 0) solde += montant;
    }
    public boolean retirer(double montant) {
        if (montant <= 0 || montant > solde) return false;
        solde -= montant;
        return true;
    }
    @Override
    public String toString() { return titulaire + " : " + solde + " euros"; }
}

        super(nom, salaireBase);
        this.chiffreAffaires = ca;

    public Technicien(String nom, double salaireBase, int heuresSup) {
        super(nom, salaireBase);
        this.heuresSup = heuresSup;
    }
    @Override
    public double salaire() { return salaireBase + 25 * heuresSup; }

public class Entreprise {
    public static void main(String[] args) {
        ArrayList<Employe> liste = new ArrayList<>();
        liste.add(new Commercial("Alice", 2000, 10000));
        liste.add(new Technicien("Bilal", 1800, 12));
        liste.add(new Technicien("Chloé", 1900, 0));
        double total = 0;
        Employe max = liste.get(0);

            System.out.println(e);             // salaire() polymorphe
            total += e.salaire();
            if (e.salaire() > max.salaire()) max = e;
        }
        System.out.println("Masse salariale : " + total);
        System.out.println("Mieux payé : " + max.nom);
    }

public class Notes {
    private ArrayList<Double> liste;
    public Notes() { liste = new ArrayList<>(); }

    public boolean ajouter(double note) {
        if (note < 0 || note > 20) return false;
        liste.add(note);
        return true;
    }
    public double moyenne() {
        if (liste.isEmpty()) return 0;
        double somme = 0;
        for (int i = 0; i < liste.size(); i++) somme += liste.get(i);
        return somme / liste.size();
    }
    public double max() {
        double m = liste.get(0);
        for (double n : liste) if (n > m) m = n;
        return m;
    }
    public void afficher() {
        for (double n : liste) System.out.print(n + " ");
        System.out.println();
    }
    public static void main(String[] args) {
        Notes n = new Notes();
        Scanner clavier = new Scanner(System.in);
        double note = clavier.nextDouble();
        while (note != -1) {
            if (!n.ajouter(note)) System.out.println("Note invalide");
            note = clavier.nextDouble();
        }
        n.afficher();
        System.out.println("Moyenne : " + n.moyenne() + " / max : " + n.max());
    }
}

Saisie 12, 25, 15,5, 8, -1 → « Note invalide », puis 12.0 15.5 8.0 et « Moyenne : 11.833333333333334 / max : 15.5 ». La lecture avant la boucle puis à la fin de chaque tour évite d'ajouter le -1.
